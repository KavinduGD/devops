# Gitlab

## Introduction

- Availble as Saas (gitlab.com) or self-hosted

## Runners

- Runners are agents that run the CI/CD jobs
- You can install the runner software on your own machine, VM, container, or cluster.
- Gitlab runner are not vms like github actions runners

## Variables

- **Predefined variables**: like CI_COMMIT_REF_NAME, CI_JOB_ID, CI_PIPELINE_ID
- **Custom variables**:
  - defined in the web UI
  - defined in the .gitlab-ci.yml file
- **File variables**: store large values or sensitive data as files
- **Secret variables**: securely store sensitive information (e.g., API keys, passwords).

## Rules

- Use `rules` to control job execution based on conditions.
- Common conditions: `if`, `changes`, `exists`, `when`.
  - `if`: Evaluate expressions based on predefined or custom variables.
  - `changes`: Trigger jobs when specific files or directories change.
  - `exists`: Trigger jobs if specific files exist in the repository.
  - `when`: Define job behavior (e.g., `on_success`, `on_failure`, `always`, `manual`).

### if

- Example:

  ```yaml
  job_name:
    script: echo "This job runs on the main branch"
    rules:
      - if: '$CI_COMMIT_REF_NAME == "main"'
        when: always
      - when: never
  ```

### changes

- Example:

  ```yaml
  job_name:
    script: echo "This job runs when files in the src/ directory change"
    rules:
      - changes:
          - src/**/*
        when: always
      - when: never
  ```

### exists

- Example:

  ```yaml
  job_name:
    script: echo "This job runs if the .env file exists"
    rules:
      - exists:
          - .env
        when: always
      - when: never
  ```

### when

- Example:

  ```yaml
  job_name:
    script: echo "This job runs on failure"
    rules:
      - when: on_success
  ```

## Artifacts

- Artifacts are files generated by jobs and can be used in subsequent jobs.
- Define artifacts in the job definition using the `artifacts` keyword.
- Example:

  ```yaml
  job_name:
    script: echo "This job generates an artifact"
    artifacts:
      paths:
        - path/to/artifact
  ```

## Git lab ecosystem

- **GitLab CI/CD**: Integrated CI/CD pipelines
- **GitLab Container Registry**: Built-in Docker registry
- **GitLab Package Registry**: Support for various package managers
- **GitLab Pages**: Static site hosting
- **GitLab Issues**: Issue tracking and project management
- **GitLab Wiki**: Documentation and knowledge base
- **GitLab Snippets**: Shareable code snippets
